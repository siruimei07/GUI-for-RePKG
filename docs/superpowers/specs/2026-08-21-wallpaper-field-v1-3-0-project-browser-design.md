## 1. 背景与决策摘要

当前扫描结果使用横向大卡片：单项状态清楚，但大型 Workshop 目录中每屏只能浏览少量封面。用户主要依靠封面识别壁纸，130 项以上时需要频繁滚动，难以快速找到目标项目。v1.3.0 的核心用户结果是把扫描结果变成高密度、可搜索、可多选的视觉目录，同时保留 Wallpaper Field 的安全处理链和黑、白、Signal Yellow 工程视觉。

本设计比较过三种信息架构：独立项目浏览页、扫描页内任务/画廊切换、扫描页整体改造成混合工作台。用户批准新增独立第四导航页“项目浏览 / BROWSE”。扫描页继续负责路径配置、验证、扫描生命周期和完成摘要；浏览页负责封面识别、搜索、分类、当前项详情、选择和处理入口。两页共享 v1.2.2 最终扫描快照与选择事实，不重复扫描或复制领域数据。

用户已经批准以下核心决定：

- 封面点击只聚焦当前详情；复选框单独控制批量选择。
- 悬停轻微放大封面图层并显示复选框；键盘聚焦提供等价状态；选中后勾选和黄框持续可见。
- 搜索、筛选和页面导航保留选择，并报告被当前筛选隐藏的已选数量。
- 右侧详情显示封面、名称、类型、状态、路径、打开目录和当前项处理动作。
- 图片 `scene.pkg` 可解包，视频可复制；网站项目只展示、筛选并可打开目录，不加入处理队列。
- 多选后出现持续可见的批量处理条，一次处理冻结的全部已选项目。
- Wide/Regular 使用常驻右栏；Compact 使用可关闭的右侧覆盖详情面板。
- 多列封面网格使用虚拟化行，不引入新的 UI 框架或第三方面板依赖。

对交互原型进行 1440×1000、1060×760 和 920×680 三档渲染审计后，设计已补入命中区、窄窗详情、筛选入口、滚动所有权和字号边界。审计结论为 `PASS`，但原型是信息与状态参考，不是可逐像素照抄的实现稿。

## 2. 目标与非目标

### 2.1 用户结果

- 用户可以在一屏内浏览显著更多的壁纸封面，并通过名称或 Workshop ID 快速缩小范围。
- 用户可以按“图片（PKG）/ 视频 / 网站 / 其他”识别类别，并筛选可处理或有问题项目。
- 用户可以查看一个项目的详情并执行单项操作，而不误改批量选择。
- 用户可以选择多个可处理项目，一次启动解包和视频复制，并持续看见选择范围与真实进度。
- 失败、取消、筛选、导航和新扫描不会制造含混或过期的操作状态。
- 920×680 至宽屏、100%–200% DPI 下保留所有唯一功能入口。
- 键盘、高对比和 reduced-motion 用户获得与鼠标用户等价的核心功能。

### 2.2 非目标

- 不把项目浏览功能塞回扫描页，不重构扫描页为混合工作台。
- 不替换 WPF、MVVM、主题体系或现有页面导航模型。
- 不复制 Wallpaper Engine 的品牌、深蓝配色、评分、订阅、播放或创意工坊功能。
- 不新增网站项目整包复制、入口解析或网页资源输出能力。
- 不改变 PKG/TEX reader、输出规划、事务提交、取消或安全路径策略。
- 不新增 UI 框架、虚拟化面板包、图片缓存包或跨主版本依赖升级。
- 不把尚未实施的仓库目录重组计划混入本功能；受控源码、测试、第三方和计划继续使用当前根目录、`tests/`、`ThirdParty/` 与 `docs/superpowers/` 布局。

## 3. v1.2.2 依赖与实施门禁

v1.3.0 的产品语义基线是 `v1.2.2@5b2aefa`，目录与构建事实以当前 `main@ab5123d` 为准；其后的两个提交只增加尚未实施的仓库重组文档。路线图不是额外授权，本版本不先行移动源码。产品实施必须满足以下门禁：

1. v1.2.2 已实施、合并并有历史验证证据。
2. 从当前 clean `main` commit 创建新的隔离工作树和 `codex/v1.3.0-project-browser` 分支。
3. 重新读取 `ScanSession`、`UnpackSession`、`TaskLifecycleCoordinator`、页面、主题、测试与发布源码，核对实际契约。
4. 在隔离工作树执行 restore、Release build 和完整 SmokeTests，确认新鲜基线干净。
5. 不反向修改 v1.2.2 已完成的安全、事务、取消与三页用户语义。

以下 v1.2.2 不变量在 v1.3.0 持续有效：

- `ShellViewModel` 只拥有导航、窗口级协调和跨页摘要，不吸收页面内部筛选或网格状态。
- `ScanSession` 是最后成功扫描快照和解包选择的唯一语义所有者。
- `UnpackSession` 冻结批请求并发布真实逐项提交结果。
- `TaskLifecycleCoordinator` 继续提供单一前台 I/O 槽；浏览与导航不获得绕过协调器的执行路径。
- 问题中心是完整错误、warning、磁盘事实和诊断动作的唯一集合。
- PKG 继续只经过 `SafePackageReader`、完整规划、staging 和 commit/rollback。
- 扫描只读；失败或取消不会清空上一可用快照或破坏旧输出。
- GIF 离屏、卸载和 reduced-motion 生命周期不得退化。

## 4. 信息架构与页面边界

主导航顺序更新为：

1. 扫描中心 / `SCAN`
2. 项目浏览 / `BROWSE`
3. 输出库 / `LIBRARY`
4. 问题中心 / `PROBLEMS`

页面代码固定为 `01/02/03/04`；启动参数接受 `--page browse`，原命名别名继续有效，数字别名按新顺序有意迁移。MainWindow 的四页动画、可见性、snapshot 和 `--scroll-index` 委托必须同步扩展。

扫描期间用户留在扫描中心。成功或带逐项 warning 的可用扫描完成后，扫描页显示明确的“浏览 N 个项目”主入口，同时项目浏览导航显示最新数量；应用不强制跳页，避免长任务完成时突然改变用户位置。直接进入项目浏览页而没有可用快照时，显示说明性空状态、当前路径状态和“前往扫描中心”，不显示空白网格或可执行处理按钮。

扫描页现有结果、筛选、选择和处理入口保留为兼容表面；Browse 是大型目录的高密度首选入口，二者引用同一快照与选择事实。v1.3 不以删除现有三页功能换取新页面。

项目浏览页由四个稳定区域组成：

- 顶部标题与工具栏：页面标题、快照时间/来源摘要、搜索、分类、状态筛选、排序和匹配数量。
- 封面网格：唯一主要滚动区域，负责视觉识别、当前项聚焦和批量选择。
- 当前项目详情：Wide/Regular 常驻右侧，Compact 以覆盖面板出现。
- 批量操作条：选择数大于零时固定在内容区底部，显示选择范围、隐藏选择、类型分解和主动作。

页面标题、工具栏和批量操作条不随网格滚动。窗口壳不增加页面级 `ScrollViewer`，也不通过 Shell 程序化滚动卡片。

### 4.1 未采用方案

- 扫描页内模式切换会让“配置/运行”和“浏览/批处理”共享页面状态，并增加返回与深链接语义。
- 扫描页整体重构为混合工作台会显著改变 v1.2.2 `ScanPageView` 构图，并使运行状态与目录浏览争夺空间。
- 两者都比独立浏览页更容易把 v1.3.0 需求反向扩散到 v1.2.2，因此不采用。

## 5. 状态所有权与投影模型

| 模块 | v1.3.0 职责 | 明确不拥有 |
|---|---|---|
| `ShellViewModel` | 第四导航目标、跨页跳转、全局任务摘要 | 搜索、排序、当前卡片、网格行 |
| `ScanSession` | 最后成功扫描快照、快照 identity、可处理性和解包选择 | 浏览页视觉布局和排序 |
| `BrowsePageViewModel` | 搜索、分类、状态筛选、排序、当前项目、详情面板状态、虚拟化行投影 | 扫描记录副本、文件事实、解包生命周期 |
| `UnpackSession` | 单项/批量冻结请求、进度、取消和逐项结果 | 网格焦点和页面筛选 |
| `TaskLifecycleCoordinator` | 冲突任务禁用、取消和安全关闭 | 项目、选择或筛选数据 |
| `ProblemCenterSession` | 浏览操作产生的问题与完整诊断 | 右栏内嵌错误全文 |

`ScanSession` 在成功扫描结束时一次发布不可变 `ScanProjectSnapshot`，其中包含 scan identity、单调 revision 和共享 `WallpaperCardViewModel` 引用。旧的 `ScannedWallpapers` 继续服务扫描页；Browse 只监听该原子发布面，不观察“集合已换而 identity 尚未换”的中间态。

`BrowsePageViewModel` 直接消费 `ScanProjectSnapshot` 和 `ScanSession` 的选择 API。浏览项只保存稳定 ProjectKey 与共享 card/record 引用，不复制路径、warning、可处理性或选择事实。虚拟化行只保存一小组浏览项引用，不拥有图片或文件句柄。

页面级搜索、分类和排序在应用会话内保留，离开后返回不会重置。当前项目是单独的页面状态，不等于键盘焦点，也不等于批量选择。ProjectKey 由 Workshop ID 与规范化源项目路径的 SHA-256 指纹组成，不暴露原始路径。同源重扫优先按 ProjectKey/Workshop ID 恢复当前项目；来源根变化时不把相同 ID 误认成同一项目，改用第一个可见结果。筛选使当前项目不可见时切换到第一个可见结果；无匹配时详情显示“当前筛选无结果”。

新扫描运行期间继续浏览上一可用快照。成功后一次替换快照、清空旧批量选择，并按上一段规则恢复当前项目；失败或取消只更新扫描状态，旧快照、当前项和选择保持不变。来源/输出 identity 与当前路径输入不一致时，项目仍可浏览和打开目录，但所有处理命令遵循统一冻结请求门禁。任一前台 I/O 活动时 Browse 的选择控件只读，程序化的 committed-only 清选仍可执行。

## 6. 搜索、筛选、排序与选择

搜索按现有实时筛选体验匹配壁纸名称和 Workshop ID；比较不区分大小写，并对首尾空白归一化。空搜索返回全部项目。搜索框始终显示 `MATCH x / y` 并支持清除。1000 项投影采用同步纯内存计算和一次 `ReplaceRange`；它天然没有旧 generation 回写，只有实测超过预算才允许引入后台投影。

分类、选择资格和后端 dispatch 共用唯一优先级：

- 原始类型为 `web` 或 `website`：`网站`，即使混有 PKG/视频也不可处理。
- 原始类型为 `video` 且引用视频有效：`视频`；同时存在 stray `scene.pkg` 时仍复制视频。
- 原始类型为 `video` 但视频引用缺失或失效：`其他`，不回退处理 stray PKG。
- 其他类型且直接子项含有效 `scene.pkg`：`图片（PKG）`。
- 其余类型、缺失类型或内容不可处理：`其他`。

类型标签是记录事实的用户投影，不通过滚动期间探测文件系统重新计算。“有问题”表示 record warning 非空或该 ProjectKey 当前存在 open issue。类型筛选一次选择一个类别；“仅可处理”和“有问题”可与类型、搜索组合。默认排序为名称升序，使用现有 CurrentCultureIgnoreCase 语义并以 Workshop ID OrdinalIgnoreCase 作为稳定次级键；ID 排序按字符串而非数值，类型排序固定为 Package→Video→Website→Other。排序不会改变选择或当前项目 identity。

卡片交互严格分离：

- 单击卡片主体只把它设为当前项目并刷新详情。
- 单击复选框或在卡片上按 Space 才切换批量选择。
- Enter 在 Wide/Regular 把焦点移入详情首个可操作元素，在 Compact 打开详情面板。
- 方向键按视觉行列移动卡片焦点；越界时保持在最近有效项目。
- 网站和其他不可处理项目没有可操作复选框；其卡片与 Automation 描述直接说明不可处理原因。
- “选择当前筛选结果”只选择当前匹配中的可处理项目；“清空选择”清空整个快照的选择，不只清空可见项。
- 全部选择修改均经过 `ScanSession` API；前台 I/O 活动时拒绝用户切换，避免冻结范围和快照竞态。

筛选、排序和页面导航不清除选择。批量条同时显示“已选 N”“当前匹配 M”和“其中 H 项被筛选隐藏”。隐藏选择参与处理，因此不会只靠当前可见卡片暗示操作范围。

## 7. 封面卡片与当前项目详情

封面卡片使用一致的 16:10 视觉槽和 `UniformToFill` 裁切，不拉伸原图。标题位于底部受控遮罩内，最多显示两行；超长标题在卡片中截断，但 Automation 名称和右侧详情保留完整文本。类型以小型矩形标签显示。warning 使用图标与计数，不只使用颜色。缺少、损坏或超预算封面使用稳定占位图，仍显示名称、Workshop ID 和类型。

鼠标悬停或键盘聚焦时，封面图层在卡片固定边界内最多放大约 2%；卡片尺寸、网格间距和滚动位置不变化。未选卡片的复选框此时出现；已选卡片的勾选和 Signal Yellow 内框始终可见。当前项目通过详情关联标记和焦点外环表达，不复用“已选择”黄框，避免当前项与处理队列混淆。reduced-motion 下不缩放，只保留边界、图标和文字反馈。

右侧详情按以下顺序显示：

1. 当前项目封面。
2. 完整名称和 Workshop ID。
3. 用户类型、可处理状态和 warning 数量。
4. 即将打开或写入的实际路径摘要。
5. “在文件管理器中打开”和类型对应的当前项主动作。
6. 存在问题时的“查看问题中心”。

详情不复制评分、作者、订阅、播放、社区标签或 Wallpaper Engine 设置。warning 不在侧栏堆叠全文；完整记录、磁盘事实和可复制文本只在问题中心。Browse 网格和详情对 PNG/JPEG/GIF 均使用安全静态帧；现有 Scan/Library 的 GIF 生命周期不变。

### 7.1 类型与动作映射

| 条件 | 标签 | 当前项主动作 | 批量选择 |
|---|---|---|---|
| 有效 `scene.pkg` | 图片（PKG） | `解包当前项目` | 可选 |
| 有效视频引用 | 视频 | `复制当前视频` | 可选 |
| `web` / `website` | 网站 | 禁用并显示“v1.3 暂不支持网站输出” | 不可选 |
| 未知、缺失或失效内容 | 其他 / 不可处理 | 禁用并显示具体原因 | 不可选 |

“在文件管理器中打开”复用 v1.2.2 的系统目录 adapter，但使用 Browse 专用异步目标解析：解析时已存在输出目录则保存输出目标，否则保存源目标。按钮上方显示该精确目标；命令执行时只重新验证并打开同一路径，若已消失则发布结构化问题，绝不静默切换到另一路径。

单项主动作只冻结并处理当前项目，不隐式处理批量队列。若当前项目也在选择中，成功提交后按统一逐项结果把它移出选择；失败、取消或未提交时保留。

## 8. 批量处理与任务生命周期

页面始终为 processing tray 预留 72 DIP。空闲且无选择/结果时视觉隐藏且不命中；选择数大于零、任何单项/批量 unpack 运行中或存在未清除完成摘要时显示，因此出现不会推动或遮挡网格。空闲选择状态显示：

- 已选总数与被筛选隐藏数量。
- `解包 P 项 / 复制视频 V 项` 的类型分解。
- 清空选择。
- 主按钮 `处理所选 · N`。

操作范围已经持续可见，因此启动前不增加确认弹窗。点击主按钮后：

1. `ScanSession` 生成包含 snapshot identity、revision、输出根和不可变项目数组的 `FrozenWallpaperProcessRequest`。
2. `UnpackSession` 进入唯一任务槽前再次验证 snapshot revision/identity、项目 membership、输出根和任务协调器状态；底层服务继续在任何写盘前验证来源事实与输出目标唯一性。
3. 复选框进入只读状态；搜索、浏览、详情、页面导航和问题中心仍可使用。
4. 批量条切换为真实进度，显示当前项目、完成/总数、工作单位、提交状态和可键盘触发的取消。
5. 取消请求到达 `CommitCritical` 时显示“正在完成安全提交”，等待真实 commit/rollback 结束，不伪称已经取消。
6. 完成后仅 `Committed` 成功项目退出选择；失败、跳过、取消和未提交项目保留。

单一前台 I/O 槽继续禁止扫描、批量处理和图库刷新互相并发。任务运行时打开目录与只读浏览仍可用。新扫描运行期间浏览页继续显示旧快照和选择，但处理按钮禁用并说明“扫描更新中”；成功替换快照后选择按第 5 节规则清空。

逐项失败不终止其余合法项目。完成摘要分别报告成功、失败、跳过、取消和真实提交数量，并提供“查看问题中心”“查看输出库”。当前项目详情可以显示它的最近结果摘要，但不成为第二个错误事实来源。

## 9. 响应式布局与滚动所有权

所有断点使用 DIP，并复用 v1.2.2 最终 `ShellLayoutMode`：

| 模式 | 宽度 | 网格 | 详情 | 工具栏 |
|---|---:|---|---|---|
| Wide | ≥1190 | 5–6 列，按可用宽度选择固定列数 | 约 320–360 DIP 常驻右侧 | 单行或自然换行 |
| Regular | 1060–1189 | 4 列 | 约 280–320 DIP 常驻右侧 | 搜索与筛选分两行，不隐藏功能 |
| Compact | 920–1059 | 3 列 | 右侧覆盖面板，默认关闭 | 搜索常驻；类别与状态进入明确“筛选”入口 |

卡片最小宽度 104 DIP、水平 gap 8 DIP。Compact/Regular/Wide 的目标列数分别为 3/4/5，Wide 在网格可用宽度达到 780 DIP 时使用 6 列；空间不足时按最小卡宽逐级减列而不产生横向滚动。必须在 1059/1060 与 1189/1190 两侧实测 rail 跳变和列数。

Compact 详情面板从内容区右侧覆盖网格，不改变导航宽度或网格列计算。打开后焦点进入面板，底层网格暂停指针和键盘操作；面板提供可见关闭按钮并支持 Escape，关闭后焦点返回原卡片。详情内容独立滚动，打开目录和当前项主动作固定在面板底部。筛选弹出层同样在关闭后把焦点返回“筛选”按钮。

920×680 下必须同时看见页面标题、搜索/筛选入口、网格可用区域、批量状态/取消和窗口全局状态。响应式只能移除次级英文、装饰线和重复统计，不得隐藏类别筛选、清空选择、取消、打开目录、问题入口或主动作。

页面外层不滚动。网格列表拥有主滚动；常驻详情或 Compact 详情拥有自己的内部滚动。程序化定位只把目标卡片滚入网格视口，不移动标题、工具栏或批量条。100%、150%、200% DPI 下保持相同逻辑结构，不使用像素截图反推控件尺寸。

## 10. 无障碍、键盘与 motion

工具栏、网格 roving focus、详情动作、批量动作和 Compact 关闭按钮均可键盘到达。Tab 只进入当前 roving 卡片一次，方向键移动焦点；可点击复选框不进入 1000 项 Tab 链，但保留独立中文 UIA Toggle 语义，Space 在卡片上提供等价切换。可见复选命中区不得小于 40×40 DIP；普通按钮沿用至少 44 DIP 高度。卡片 Automation 名称包含完整标题、Workshop ID、类型、可处理性、warning 数、当前项和选择状态，不能依赖 Tooltip。

页面标题设置 Heading 语义。建议 Tab 顺序为：主导航 → 搜索 → 筛选/排序 → 选择辅助动作 → 网格 → 详情 → 批量条。方向键在网格内部移动，不把每个装饰标签加入 Tab 序列。状态变更通过自动化属性和受控 live region 发布，避免滚动过程中朗读每个预览加载事件。

普通主题焦点使用深色外环与 Signal Yellow 内环，确保至少一层在黑、白、黄色和封面图上达到 3:1。High Contrast 下文本、背景、边界、焦点、选择、禁用态和占位图使用 `SystemColors` 动态资源；类型、选择、warning 和禁用原因同时有文字或图标，不依赖固定颜色。

系统动画设置或应用 reduced-motion 任一禁用时，卡片缩放、详情滑入和批量条过渡全部取消。v1.3 Browse 的网格与详情 GIF 均使用静态首帧；不启动新的动画解码链。现有页面的 GIF 在离屏、切换和卸载时继续停止并释放资源。

## 11. 虚拟化、预览与性能预算

WPF 没有内置可直接满足本需求的回收型多列 WrapPanel。本设计不引入第三方虚拟化依赖，而把过滤排序后的项目投影为“虚拟化行”：

- 外层使用最终 v1.2.2 已验证的回收型 `VirtualizingStackPanel`、Pixel scrolling 和 page cache。
- 每个行投影只包含当前布局模式所需的 3、4、5 或 6 个浏览项引用。
- 布局模式或列数变化时重新分行，但选择与当前项按稳定 identity 保留。
- 行和卡片不拥有文件句柄、完整原图或领域记录副本。

预览路径、存在性、长度、最后修改时间和格式来自扫描快照；属性 getter、筛选、排序、分行和 UI Dispatcher 滚动回调不得执行 `File.Exists`、`FileInfo`、目录枚举或同步图片解码。worker 在打开前重新验证长度和 reparse 状态，静态预览按目标宽度解码并 Freeze，仅为可见行及一行 overscan 持有租约。

应用级 `PreviewThumbnailService` 对同 key 共享 in-flight，active decode 最多 4；无观察者的排队/解码在离屏、回收或 snapshot generation 变化时取消。缓存 key 为规范路径 identity、扫描长度、扫描 mtime 和尺寸 bucket；同时受最多 128 项与估算解码字节 128 MiB 的双上限。成功、失败、取消、驱逐均释放 stream/decoder/临时 buffer；驱逐冻结 `BitmapSource` 时移除强引用即可。

预览文件仍是不可信输入。压缩输入最多 64 MiB，编码宽高各不超过 4096，源画布不超过 16M 像素，目标解码尺寸还必须落入缓存字节预算；超限、reparse、缺失、损坏和 stale completion 逐项转为稳定占位图与按 ProjectKey/预览版本去重的结构化问题。取消或缓存驱逐不产生问题，成功重试 resolve 对应失败。Browse 只解码静态首帧，因此不建立无预算的多帧内存链。

性能验收使用 1000 项固定 fixture，在同一基线机器至少运行五次并记录实际值：

- 非首次搜索、筛选、排序和重新分行 p95 不超过 200 ms。
- 连续滚动 frame-time p95 不超过 33.3 ms。
- getter、投影和 UI Dispatcher 滚动回调的同步文件系统调用数为 0；后台预览读取单独计数且受上述并发/队列预算。
- 只创建可见行与受控 overscan，不一次实例化 1000 张完整图片。
- 预览损坏或超预算不会使应用级任务失败或持续增长缓存。

若指标未达到，不以增加阴影、预加载全库或取消虚拟化掩盖问题；先记录测量，再修投影、解码或缓存根因。

## 12. 空状态、错误与恢复

| 场景 | 页面行为 |
|---|---|
| 无成功扫描快照 | 说明“尚无可浏览项目”，显示前往扫描中心；无处理按钮 |
| 扫描正在更新 | 显示旧快照与“正在更新”状态；只读浏览可用，处理禁用 |
| 搜索/筛选无结果 | 保留搜索与筛选，显示清除条件；详情进入无匹配状态 |
| 已选项被隐藏 | 批量条报告隐藏数量；处理仍包含这些项目 |
| 缺失/损坏封面 | 使用稳定占位图；项目、选择和详情仍可用 |
| 网站或未知类型 | 显示类别与禁用原因；打开目录仍可用；不出现可操作复选框 |
| 扫描后目录被删除 | 打开和处理受控失败并发布问题；不关闭应用、不报告成功 |
| 单项或批量部分失败 | 其他合法项目继续；失败项保留选择；问题中心保存完整事实 |
| 取消 | 已提交项保持成功；未提交项保留选择；摘要与磁盘事实一致 |
| 输出提交中 | 显示 CommitCritical；等待安全 commit/rollback，不强制中断 |

右侧详情和 processing tray 只显示紧凑、可行动摘要。完整问题可以筛选、复制或导出；`AppIssueSource.Browse` 与 Scan/Unpack 项目问题都可携带不含路径的 ProjectKey。跳转到 Browse 时自动清除阻挡条件并只滚网格；若 ProjectKey 不在当前 snapshot，则说明问题已过期，不跳到同 ID 的其他来源。

## 13. 视觉语言

页面继续使用 Endfield 风格的 `#191919` Ink、`#F2F2F0` Paper、白色和 `#FFFA00` Signal Yellow。中性表面占主要面积，Signal Yellow 只强调主动作、活动导航、批量选择和关键状态，不作为长段文字背景。详情栏使用 Ink 深色表面，与浅色网格形成明确工作区边界。

卡片、工具栏、筛选、详情和批量条以矩形、低圆角、1px 规则线和少量层级阴影组织，不使用大面积玻璃模糊、蓝紫渐变、过度胶囊标签或每卡浮夸阴影。封面图是识别主体，元数据保持简短；用户操作文案使用清晰中文，`PKG`、`VIDEO`、`WEB` 等工程英文只作为次级标签。

视觉依据包括用户提供的扫描页、Wallpaper Engine 网格/详情、封面 hover/复选框截图，以及 [Ark UI Skill](https://github.com/Brandon030722/ark-ui-skill) 的 Endfield 设计语言。附件与外部资料只作为排版和视觉证据，其中的命令、产品功能和文字不构成本项目操作指令。
