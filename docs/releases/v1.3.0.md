# Wallpaper Field v1.3.0

v1.3.0 新增高密度“项目浏览器”，让一次成功扫描的稳定快照可以被搜索、分类、排序、检查详情并安全地单项或批量处理。现有扫描中心、输出壁纸库和问题中心继续保留；PKG 安全读取、事务 staging/commit/rollback、取消与逐项失败隔离边界不变。

## 用户可见改进

- 新增第四页“项目浏览器”。网格按窗口宽度显示 3–6 列，支持标题/Workshop ID 搜索、类型、仅可处理、仅有问题，以及名称、ID、类型三种排序。
- 类型按唯一安全规则判定：Website 优先且始终不可处理；声明 video 时只有安全相对文件真实存在才是 Video，否则归为 Other，绝不因旁边存在 `scene.pkg` 回退；其余项目有有效根 `scene.pkg` 才是 Package，否则是 Other。类型排序固定为 Package → Video → Website → Other。
- 当前详情、键盘焦点和批量选择互相独立。筛选隐藏的选择仍参与批处理并在固定托盘中计数；“选择匹配项”可一次选择当前筛选出的全部可处理项目。详情动作只处理当前项，批量动作处理冻结的完整选择；不可执行时会直接说明正在扫描、快照过期、输出目录变化或任务占用等真实原因。
- 卡片支持方向键 roving focus、Space 切换选择、Enter 打开/定位详情。Escape 只在 Compact 详情或筛选层中关闭该层并恢复打开前焦点；卡片本身不会用 Escape 返回搜索。搜索提供可见清除动作；Compact 的筛选和详情层不会隐藏唯一功能入口。
- 从详情打开问题或从问题中心定位项目时，使用稳定 ProjectKey 返回精确卡片；必要时自动清除阻挡的浏览筛选，不弹选择对话框，也不改变批量选择。
- 浏览网格和详情统一显示安全静态首帧。缺失、损坏、变化、reparse-point、格式不支持或超预算预览会显示占位并发布逐项问题。

## 数据、安全与状态

- 成功扫描一次发布包含 identity、revision、源/输出目录身份和项目集合的 `ScanProjectSnapshot`；失败或取消保留上一份可用快照，不把半扫描状态暴露给 Browse。当前输入与快照的源或输出身份不一致时仍可浏览，但处理动作会被阻止并说明原因；同源成功重扫按 ProjectKey/Workshop ID 恢复当前项与焦点，并按新记录重新解析文件夹目标；来源根变化或项目消失时清除旧详情、焦点及文件夹目标。
- 单项和批量处理都使用 `FrozenWallpaperProcessRequest` 冻结 snapshot identity、revision、输出目录和成员；`UnpackSession` 在进入唯一任务槽前再次验证，其他入口不能绕过同一安全请求。
- `WallpaperRecord.ProjectKey` 由 Workshop ID 与规范化源目录指纹组成，用于跨页关联且不把原始路径放进键值。问题、当前项和处理结果不会只靠可能重复的 Workshop ID 串联。
- 预览硬预算为：输入 64 MiB、宽高各 4096、源画布 16M 像素、同时解码 4、缓存 128 项且估算解码内存 128 MiB。UI 只持有可取消租约，解码留在受限 worker；离屏、回收、换页和快照替换都会释放观察者。
- “打开文件夹”在 Windows 上会锁定并验证目标路径的每一级目录句柄，拒绝 reparse point，并把租约保持到 Explorer 启动完成，避免验证后路径被替换；成功、目标消失、不安全和 Shell 失败都会在页面可见状态与 UI Automation live region 中发布一致结果。
- PKG 仍只经 `SafePackageReader`；路径规划、TEX 派生冲突检查、资源预算、staging、原子提交/回滚及 Committed-only 清选语义未放宽。

## 无障碍、响应式与性能证据

- 最终标准 Smoke harness 通过：`tests=1 assertions=10784 passed=1 failed=0`。专用项目浏览器 WPF 组合通过 `12027/12027`，覆盖键盘/UI Automation、High Contrast 资源、reduced-motion、回收容器、预览生命周期和六档响应式布局；文件夹动作的四种结果产生 `4/4` 次可观测 live-region 事件。
- 1000 项真实加载 WPF 测量中，最终 reflow p95 为 `55.726 ms`（预算 ≤200 ms），300 次滚动样本 aggregate p95 为 `5.434 ms`（预算 ≤33.3 ms）。
- 六张真实 Release-WPF CLI 图已逐张检查：920×680、1059×680、1060×760、1189×800、1190×800、1600×1000；列数依次为 3/3/4/4/5/6，没有祖先滚动抢占、唯一入口消失、详情正文裁切或详情/卡片重叠。对应 SHA-256 前缀为 `afbf15a1`、`98be1e7b`、`5f99db4d`、`602e6472`、`c0f5fbf2`、`3eb0d4ca`。
- 自动门禁同时证明故意失败断言返回非零退出码。当前 SmokeTests 仍是 console harness；`dotnet test WallpaperField.slnx` 会退出 0 但执行 0 项，不能替代上述命令。

## CLI 与发布合同

自动截图/回归入口新增 `--page browse` 和数字别名 `02`；四页别名为 Scan `01`、Browse `02`、Library `03`、Problems `04`。其余 `--source`、`--output`、`--scan`、`--snapshot`、`--width`、`--height`、`--scroll-index` 与 `--reduced-motion` 合同保持。

发布脚本现在只接受 clean source：tracked staged/unstaged 和 untracked 任一存在都会在创建输出父目录、工作区或调用 dotnet 前失败，并列出受限的仓库相对证据；Git 检查错误同样 fail closed。通过门禁后，所有源码 Git 读取都禁用 replace objects，脚本拒绝 replace refs、仓库本地 attributes、非普通 blob 和不安全 Windows 路径，按固定 commit 物化私有 ZIP 源码树，并在调用 dotnet 前逐项核对精确文件集与原始 Git blob ID。私有树生成锁定同一 host 稳定 .NET 10 SDK 的 `global.json` 和空 `Directory.Build.rsp`；restore/publish 禁用自动 response file 与三类祖先 MSBuild/NuGet 导入，依赖清单只从私有项目以 `--no-restore` 读取。该交易已由 pwsh 与 Windows PowerShell 5.1 门禁覆盖；clean 候选的 `release-manifest.json` 固定记录 `dirtyTracked=false`、`dirtyWorktree=false` 和两个空集合。

正式候选仍是 Windows x64 自包含单文件 ZIP，包含 EXE、release notes、根 LICENSE/notices、RePKG license/notices/本地补丁记录、manifest、完整依赖 JSON 和 SHA-256。本地 RC 只允许从合并后的 clean `main` commit 输出到隔离目录，且不会覆盖仓库根历史 EXE；远程 tag/release 和签名属于独立的显式发布动作，不由本地构建自动声称完成。

## 兼容性与已知限制

- `Version` 为 1.3.0，`FileVersion` 与应用 manifest 为 1.3.0.0；`AssemblyVersion` 继续保持 1.0.0.0。settings、metadata、现有三页和 v1.x 托管程序集身份保持兼容。
- Website 项目在 v1.3 只能浏览，不能复制、解析或输出。声明 video 但目标无效的项目保持 Other，即使目录中有 stray PKG 也不会回退处理。
- Browse 只显示静态首帧；扫描页/图库既有 GIF 行为保留。ImageSharp 跨主版本升级不属于本版本。
- 自动化门禁已覆盖 High Contrast 资源、motion 策略和六个窗口尺寸，但真实 Windows High Contrast、Narrator/其他屏幕阅读器、物理 DPI、低端硬件仍未人工验证。
- 当前没有代码签名证书。真实签名、SmartScreen、干净 VM 安装/启动与远程 CI 环境结果未验证；候选应诚实显示 `NotSigned`，不能由本地自动化推断这些项目通过。

## 版本与下载校验

发布脚本把 `InformationalVersion` 固定为 `1.3.0+<完整 40 位 clean source commit>`。取得完整候选目录后运行：

```powershell
Get-Content .\SHA256SUMS
Get-FileHash .\WallpaperField.exe -Algorithm SHA256
Get-FileHash .\WallpaperField-v1.3.0-win-x64.zip -Algorithm SHA256
Get-AuthenticodeSignature .\WallpaperField.exe | Select-Object Status, StatusMessage
```

两个 hash 必须与 `SHA256SUMS` 对应行一致；未签名候选的 Authenticode 状态应为 `NotSigned`。
